# 内容蒸馏

## 何时使用

用户说「把这本书 / 这期播客 / 这门课做成 skill」「蒸馏这个方法」「读完想带走能用的东西」时。

不是做书摘、读后感或作者角色扮演；只产出**能在真实场景里执行的能力**。

## 五步流程

### 1. 整体理解

用 5 句话写清：核心命题、论证结构、适用对象、前提条件、作者没解决的问题。缺这部分，后面的方法单元会碎片化。

### 2. 抽方法单元

只抽这几类可执行内容：

- 决策框架（在什么条件下选什么）
- 操作流程（步骤、顺序、输入输出）
- 判断规则（阈值、信号、反例）
- 清单与检查表
- 计算或表达模板

概念、故事、金句只作为解释材料，不单独成 skill。

### 3. 三重验证

每个候选单元逐条过：

1. **可执行**：换一个人能不能照做？
2. **有边界**：知道什么时候不适用吗？
3. **可复用**：能在多个真实场景里调用吗？

三条都过才保留；只过一条的写成「参考」，不写成 skill。

### 4. 写成 Skill

每个 Skill 用统一结构：

```markdown
---
name: 中文名（≤12 字）
description: 一句话说明何时使用
---

# 名称

## 何时使用
## 输入
## 步骤（3–7 步）
## 输出格式（给最小示例）
## 检查清单
## 反例 / 边界
```

要求：

- 步骤必须能直接执行，不写「深入分析」「综合考虑」。
- 每条规则尽量带条件、阈值或判断信号。
- 反例写具体失败场景，不写「注意不要出错」。
- 一个 Skill 只解决一类问题；能力太多就拆开。

### 5. 收口

- 给出一句「这套 skill 最适合谁、在什么场景下用」。
- 标出来源与局限：样本范围、时代背景、作者立场。
- 不复制原文长段；用自己的话重写方法与步骤。

## 输出格式

```text
来源与范围：……
核心命题：……
保留的方法单元：1 / 2 / 3（各自通过哪三重验证）
Skill 文档：……（按上面的结构）
适用与不适用：……
```

## 反例

- ❌ 把目录改写成「第 1 章讲了……」——这是书摘，不是 skill。
- ❌ 只有原则没有步骤：「要保持长期主义」。
- ❌ 把作者的个人经历当成普适方法。
- ❌ 一个 skill 塞进二十条互不相关的建议。
