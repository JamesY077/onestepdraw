# AI 项目评估

## 何时使用

要把「我们也要用 AI」变成具体项目，或评估一个 AI 功能是否值得投入时。

## 七格画布

1. **业务问题**：谁在什么流程里卡住？用时间、成本、转化、错误率描述现状。
2. **AI 是否必要**：规则/脚本能解决就不要上模型；需要感知、生成、预测、理解非结构化内容时才用。
3. **数据**：输入从哪来、是否合法、标注成本、多久能拿到第一批可用样本。
4. **模型能力边界**：能做 80 分的事是什么？哪 20% 必须由人兜底？
5. **人机流程**：AI 输出进入哪个环节？谁审核？出错如何回滚？
6. **试点**：选一个部门、一个场景、2–4 周，明确基线、指标、通过标准。
7. **风险**：隐私、版权、幻觉、偏见、供应商锁定，各写一条缓解措施。

## 工作步骤

1. 先写「不做 AI 的替代方案」，确认它为什么不够。
2. 用七格画布补齐信息，缺的标成待验证，不要脑补。
3. 给出一个最小试点：范围、周期、人力、预算、成功指标。
4. 写出试点失败后的退出条件与可复用资产（数据、流程、组件）。

## 输出格式

```text
业务问题与基线：……
替代方案：……
七格画布：……（每格 1–2 句）
最小试点：范围 / 周期 / 参与人 / 指标 / 通过标准
主要风险与缓解：……
建议：立项 / 先验证数据 / 暂不做
```

## 检查清单

- [ ] 指标是业务指标，不是「模型准确率」本身？
- [ ] 有明确的人工兜底与回滚路径？
- [ ] 数据来源合法，且拿得到？
- [ ] 试点周期足够短，能快速证伪？
- [ ] 失败后能留下可复用的数据或流程吗？
