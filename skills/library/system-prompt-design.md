# 系统提示词设计

## 何时使用

要为一个 Agent、写作助手、客服、分析工具写系统提示词，或现有提示词输出不稳定时。

## 八个区块

1. **角色**：一句话说明它是谁、服务谁，不写形容词堆砌。
2. **目标**：用可验收的结果描述，例如「输出 5 条带出处的结论」。
3. **输入**：说明会收到什么、哪些字段可信、缺信息怎么办。
4. **步骤**：3–6 步，按执行顺序写；复杂任务先计划再执行。
5. **工具**：每个工具的能力、参数、调用时机与禁止场景。
6. **输出格式**：给一个最小示例；字段名固定，避免模型自由发挥。
7. **边界**：不能编造、不能越权、不能承诺的事，逐条写清。
8. **失败处理**：信息不足、工具失败、结果冲突时分别怎么做。

## 工作步骤

1. 写 5 条真实输入，覆盖正常、边界、恶意、缺信息、超长五类。
2. 先写输出契约，再写步骤；不要先写一大堆角色设定。
3. 把「要专业、要准确」改成可检查的规则（例如「每个数字附来源与日期」）。
4. 用 5 条输入各跑一次，记录跑偏点，只改对应区块。
5. 删除重复约束；同一规则只出现一次。

## 输出格式

```text
# 角色
# 目标
# 输入
# 步骤
# 工具
# 输出格式（附最小示例）
# 边界
# 失败处理
# 评测用例（5 条：输入 → 期望 → 检查点）
```

## 检查清单

- [ ] 每条要求都能被观察或检查？
- [ ] 输出格式有示例，字段名固定？
- [ ] 工具调用时机与禁止场景都写了？
- [ ] 缺信息时的行为明确（问 / 标假设 / 停止）？
- [ ] 5 条评测用例能覆盖主要失败模式？
