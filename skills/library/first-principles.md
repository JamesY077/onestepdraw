# 第一性原理

## 何时使用

遇到「行业都这么做」「只能这样」的僵局，或需要为一个新产品、新流程找根本解时。

## 四层拆解

1. **目标层**：真正要达成的结果是什么？用可观测的指标写，不写「更好」。
2. **事实层**：哪些是物理、法律、预算、时间上的硬约束？逐条写出证据。
3. **假设层**：哪些只是惯例、习惯、别人的做法？标出「如果它不成立会怎样」。
4. **方案层**：在硬约束内重新组合，不继承未经验证的假设。

## 工作步骤

1. 用一句话重写问题，去掉方案词（不要一上来就说「做个 App」）。
2. 列 5–10 条「大家默认成立」的假设。
3. 对每条问三次「为什么必须这样？」，直到触到事实或触到「其实没人规定」。
4. 只保留事实约束，重新生成 3 个方案。
5. 给每个方案设计一个 1–3 天能完成的最小验证，明确通过/失败标准。

## 输出格式

```text
问题重写：……
硬约束：……（每条附证据）
可移除假设：……（每条写「如果不成立」）
重建方案：A / B / C（各自的第一性原理依据）
最小验证：对象 / 动作 / 指标 / 通过标准 / 时间盒
```

## 检查清单

- [ ] 方案里还藏着「因为别人也这么做」吗？
- [ ] 硬约束都有证据，而不是感觉？
- [ ] 三个方案真的不同，而不是同一方案的包装？
- [ ] 验证能在几天内给出明确结论？
- [ ] 失败时知道该改哪条假设？
